### Aggregate view: theme / color token drift (AD-10)

Scope: every `.css`, `.ts`, `.tsx` and `.jsx` under `asprinkleofcode/src`, scanned for primitive ramp variables, raw hex, `rgb()` and raw Tailwind palette classes outside `src/theme/`.

- **Checked and clean, Epic 1 surfaces.** No component, page, or lib file written in Epic 1 references a primitive ramp, raw hex, or a palette class. The role-token values in `src/theme/colors.css:34–74` match `DESIGN.md` v0.9 frontmatter `colors` exactly, including the §18a fill and focus values and `glow.woodcraft`. Every role-token text pair in use passes AA. The lowest is `text.secondary` on `background.secondary` at 5.21:1, and `border.essential` on `background.secondary` is 3.94:1, which passes 1.4.11 non-text contrast.
- **F-1: Legacy `App.css` is global, unlayered, and uses primitive tokens. It overrides role-token utilities on Story 1.3 surfaces that never got the reset.** `src/App.css:9–30` styles bare `h1`/`h2`/`p` with `--color-dark-800` text-shadow, `--color-primary-100` text and fixed sizes. `App.tsx:1` imports it for every route. Because the rules are unlayered, they beat Tailwind's layered `type-*` and `text-*` utilities. Story 1.6 discovered this, and Stories 1.6 and 1.7 patched only their own components (`Recognition.css`, `ExplorationPaths.css`, `EvidenceHighlights.css`, `PathIndex.css`). The Story 1.3 surfaces built before the discovery were never revisited: `pages/NotFound/NotFound.tsx:7–10`, `components/ErrorBoundary/ErrorBoundary.tsx:41–44`, `pages/WorkStory/WorkStory.tsx:21–22` and `pages/Personal/Personal.tsx:15–16`. **Observed at runtime** (`vite preview`, 1024px): `/#/does-not-exist` and `/#/engineering/no-such-slug` render the h1 at **64px with a `rgb(30,30,47)` 15px text-shadow** (spec: `type-section`, 22px) and the paragraph at **21.6px in `#FCE7F3` = `--color-primary-100`** (spec: `type-body`, 16px, `text.secondary`). `/engineering` and `/beyond` measured correctly at 22px / 16px `#9C9CBA`. This is AD-10 drift that no test catches (jsdom ignores cascade layers) and that sits on a story boundary: 1.3 built the pages, 1.6 discovered the cause, 1.7 documented the reset as "the pattern to follow" (`spec-1-7…md:54–55`) for new components only. `deferred-work.md:64` tracks the root cause but not these four live surfaces.
- **F-2: `App.css` re-imports Tailwind, so the built CSS ships it twice.** `src/App.css:1–3` repeats `@import "tailwindcss"` plus the flowbite plugin and `@source` that `src/index.css:1–5` already declares. This predates Epic 1, but Story 1.8 edited this file (`fcb5a03`) without removing it. It doubles the base and utility CSS and adds a second ordering source between the two utility layers.

### Diff-scope review (`bmad-review`: adversarial, edge-case-hunter, verification-gap)

Run over `12c3366^..92c41a8` app code (5,665-line diff, lockfile and binary assets excluded), weighted to story boundaries and AD-10. The three lenses ran independently. Their findings are merged below, and the lenses that raised each one are noted (ADV / EC / VG). Every finding kept here was re-checked against source or runtime. Findings that did not hold, or that the owner's decisions already cover, are listed at the end.

**Escalations of aggregate findings**

- **F-2 escalated: the second Tailwind root silently undoes the font token** (ADV, EC). The built CSS sets `--font-sans` to the DESIGN §8 system stack at byte 1239, then **resets it to Tailwind's default `ui-sans-serif,…` at byte 39536**, which comes from `App.css`'s own `@import "tailwindcss"`. **Runtime:** `getComputedStyle(body).fontFamily` and the Recognition `h1` both resolve to `ui-sans-serif, system-ui, sans-serif, …`. So the UX-DR20 / Story 1.1 font stack has never applied anywhere on the site, and any later `@theme` override of a Tailwind default key would be undone the same way.
- **F-1 widened: MDX bodies will inherit the bleed** (ADV, EC, VG). `WorkStory.tsx:23` and `Personal.tsx:17` render `<Body />` inside an unprotected `div`, so every `p`/`h2` an MDX story emits gets `App.css`'s 0.75rem (mobile) `--color-primary-100` paragraphs and 2rem `h2` with text-shadow. The first real story in Epic 2 will ship like that, and no test reads cascade results (`grep getComputedStyle|revert-layer|App\.css` across all tests returns nothing).

**New findings**

- **R-1: A PUSH navigation into a route that throws never settles AD-19 scroll or focus** (ADV, EC, VG). `App.tsx:54–73` puts `<RouteSettled>` inside `<ErrorBoundary>`. When the route throws or its chunk fails, the boundary replaces its children, so `settle()` never runs: no scroll to `<main>`, no focus on "Something went wrong", and `paused` in `useNavigationScroll.ts:61` stays true, so scroll recording stops. Every App test that reaches the fallback starts there with `renderAt(...)` (`App.test.tsx:168–169, 192, 335`), and none navigates into it.
- **R-2: A failed lazy chunk is cached for the whole session** (ADV, EC). `lib/storyBody.ts:15–19` keeps each `lazy()` in a module-level `Map`, and `React.lazy` memoises a rejected import. The route-page lazies in `App.tsx:14–24` behave the same way. One dropped request, or a GitHub Pages redeploy that removes old hashed chunks, leaves that story or page broken until a full reload. That contradicts the fallback's own text ("The navigation above still works, or you can try again").
- **R-3: Focus indicator disappears in forced-colors mode** (ADV). `focusRing` (`aSprinkleOfCodeTheme.ts:8–9`) pairs `focus:outline-none` with a box-shadow ring. In Tailwind v4, `outline-none` compiles to `outline-style:none` (verified in the built CSS), and forced-colors mode removes box-shadows. Every themed control (nav links, toggle, footer icons, text links, Explore tiles, buttons) then has no visible focus in Windows High Contrast. Tailwind v4's `outline-hidden` exists for exactly this case. `Header.css` already handles forced colors for the logo, but not for focus.
- **R-4: Mobile nav toggle exposes no expanded state** (ADV). **Runtime:** the `NavbarToggle` button carries only `data-testid` and `class`, with no `aria-expanded` or `aria-controls` (flowbite-react 0.12.5 does not add them). This is a WCAG 4.1.2 name/role/value gap on the mobile menu.
- **R-5: The copyright reads "© 2026Alisha Korba"** (ADV). **Runtime** `textContent` confirms it. `FooterCopyright` separates the parts with only an `ml-1` margin, and `Footer.test.tsx:98` asserts the missing space, so the test locks the defect in.
- **R-6: AD-10 has no automated guard outside two flowbite cases** (ADV, VG). `src/test/expectNoFlowbiteDefaults.ts:13` rejects only `dark:` and `gray-` classes. Primitive arbitrary values (`text-[var(--color-dark-300)]`), raw hex, and other palette utilities (`text-slate-400`) pass. No lint rule or test scans `.css`/`.tsx` for `--color-(primary|dark)-`. The Tailwind default palette is still enabled. Today's clean state therefore depends on discipline, not a gate. This is the upstream lesson behind F-1 and F-4.
- **R-7: The registry's real globs are never exercised with content** (VG). `registry.test.ts:142–145` checks only `Array.isArray(entries)` over an empty `src/content/`. The integration test loads a hand-copied `plugins/__fixtures__/*/src/lib/fixtureRegistry.ts` ("the same globs and options as src/lib/registry.ts"), and `App.test.tsx` mocks `./lib/registry` wholesale. Dropping `import: "frontmatter"` from `registry.ts:73–78` would type-check and pass every test.
- **R-8: Person JSON-LD has a fragile `image`, and there is no `og:image`** (ADV, EC). `index.html:42` points `image` at the content-hashed `assets/alisha-sprinkle-korba-headshot-BqFgpPGr.jpg`. That hash is already tracked (`deferred-work.md:35–37`). New: there is no `og:image` or `twitter:image`, and `twitter:card` is `summary` (`index.html:26`), so link previews (the AD-14 / FR-23 share path) show no portrait.
- **R-9: `ExternalLink` freezes the whole label on one line** (ADV). `ExternalLink.css:2–4` applies `white-space:nowrap` to the full link, not just the last word and arrow. Any multi-word outbound link from frontmatter or MDX in Epics 2–4 will overflow at 320–375px.
- **R-10: Frontmatter rules leave two gaps** (ADV). `hero` is only `nonEmptyString` (`frontmatter.ts:165`), with no shape or existence check like `pdf` has. `featured` is not unique per path (`registry.ts:28–29` tie-breaks silently), so a duplicate silently changes the homepage Highlight. Both are latent until Epic 2 content arrives.
- **R-11: Theme motion is not gated for reduced motion** (ADV). `button.base` uses `transition-all duration-200`, and `avatar.root.inner` uses `hover:scale-[1.03]` and `avatar-pulse` (see F-4) without `motion-safe:`, while the footer icons do gate. The impact is low (a hover transition), but it is inconsistent with AD-13.
- **R-12: The ambient field fades in again on every navigation** (ADV). `App.tsx:49` remounts `AmbientLayer` per `location.key`, which is the intended design ("freshly shuffled field"). But `.ambient-layer`'s 1.2s `ambient-fade-in` (`AmbientLayer.css:12`) also replays each time, including a brand-link click while already on `/`. Whether that reads as calm or as flicker is a UX call.
- **R-13: Minor edge cases, low impact.** (a) `ErrorBoundary.componentDidUpdate` (`:31–35`) can clear an error that was thrown in the same update that changed `resetKey`, giving one extra throw and log (EC). (b) `isNavActive.ts:5–7` compares case-sensitively while the router matches case-insensitively, so `#/Engineering` shows no active link (EC). (c) Scroll positions live in memory only, so reload-then-Back lands at the top (EC). The spec says "in memory only" (`useNavigationScroll.ts:18`), so this is by design. (d) Low confidence: draft bodies may still emit a chunk named after the draft file (EC). Unverifiable until a draft exists.
- **R-14: `App.test.tsx` is a single shared file** (see F-8).

**Dropped or not carried forward**
